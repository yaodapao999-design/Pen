# GDD：对手 AI 与弹射物理预测指示

本文档定义 **Pen**（桌面物理对战：拖拽弹射钢笔、冲量与旋转、击落对手）中 **敌方行为** 与 **玩家弹射前的轨迹/落点预测表现** 的设计意图、规则边界与验收标准。实现细节见本目录下实现计划。

**关联项目总览**：`../Project-Overview.md`（战斗状态机 `Idle → Action → Result`、`BattleContext`、`PenEntity.Launch` 等）。

---

## 1. 设计目标

### 1.1 对手 AI

- 在 **玩家回合外的合法时机**（见 §3），由系统控制 **敌方笔** 完成与玩家同构的弹射决策：选择施力点、拖拽方向与力度，使对局在没有真人对手时仍可完整循环。
- AI 难度应 **主要由数据与策略层调节**（反应误差、规划深度、风险偏好），而非硬编码单一路径，便于后续里程碑扩展「性格」与零件联动。
- AI 行为在观感上符合物理直觉：不明显作弊（除非明确设计的「街机补偿」并写入非目标/配置），避免破坏「笔的重量感」。

### 1.2 弹射物理预测指示

- 在 **玩家处于可弹射的交互状态**（通常为 `IdleState` 下的拖拽蓄力阶段）时，提供 **可读、低误导** 的预测反馈，帮助玩家理解「施力点 + 方向 + 力度」与可能轨迹的关系。
- 预测表现与 **真实物理** 的差异必须在设计层显式分级（见 §4），避免玩家形成错误肌肉记忆后产生挫败感。

---

## 2. 核心玩法语境（与现有代码对齐）

| 概念 | 说明 |
|------|------|
| 双笔实体 | `PenEntity`：玩家 `pen`、对手 `enemyPen`（`BattleContext` / `BattleStateMachine`） |
| 弹射 | `PenEntity.Launch(direction, force, contactPointWorld)`：`AddForceAtPosition` 冲量 + 零件弹射倍率 + 笔身恒定阻力（`FixedUpdate`） |
| 战斗子状态 | `IdleState` → `ActionState`（发射与结算过渡）→ `ResultState`；停稳后回到 `IdleState` |
| 胜负 | 台面掉落阈值 `HasFallen`；双方停稳且无掉落则回到等待 |

本 GDD 不改变上述胜负与状态机外壳，仅在 **回合归属、输入源、表现层** 上扩展。

## 3. 回合与控制权

### 3.1 默认规则（推荐基线）

- **回合制弹射**：同一时刻仅一方进行蓄力与发射授权；另一方刚体可保持动力学响应，但 **不接受拖拽输入**。
- **顺序**：里程碑 1 可采用固定 **玩家先手 → 敌方 → 循环**；后续可扩展为抛硬币、零件效果或 UI 选择。

### 3.2 AI 决策时机

- AI 仅在 **轮到敌方且处于 Idle（或等价「可规划」子状态）** 时运行规划管线；进入 `ActionState` 后仅播放已提交指令，不再改参数。
- AI 从「开始思考」到「提交发射」之间可有 **可配置延迟**，避免机器感瞬发；延迟内若状态非法（如已被暂停），应取消提交并 fail-fast 打日志。

### 3.3 与现有 `ActionState` 的关系

- 当前 `ActionState` 仅对 `ctx.pen` 调用 `Launch`。扩展后应通过 **统一发射入口**（例如始终对「当前行动方笔」发射）或 **并行的敌方 ActionState 路径** 实现，具体以实现计划中的脚本契约为准；GDD 要求：**玩家与敌方共用同一套冲量语义**，避免双轨物理。

## 4. 物理预测：精度分级与玩家契约

真实笔体含 **可变质量/惯量、施力点扭矩、零件 `GetLaunchMultiplier()`、恒定线/角阻力** 等，完整解析轨迹成本高且可能与 Unity 求解器存在偏差。设计层采用 **三级预测契约**（实现可选用其中一级起步，但必须标明所用级别）：

| 级别 | 描述 | 玩家契约 |
|------|------|----------|
| **L0 几何示意** | 仅显示拖拽向量、最大弦长、施力点法线等，不做时间积分 | 「方向与施力点提示」，不承诺落点 |
| **L1 质点近似** | 将笔视为质心受冲量 + 简化阻尼的抛物/指数衰减近似 | 「趋势正确」，不保证与刚体旋转一致 |
| **L2 刚体镜像仿真** | 固定时间步、复制关键物理参数与力的施加方式，在隔离场景或 `Physics.Simulate` 管线中步进 | 「高置信」，仍允许与实机帧间差异的免责声明 |

**非目标（预测）**：里程碑内不承诺预测考虑 **笔-笔碰撞、台缘复杂摩擦、零件特殊 OnLaunch 持续力**（如火箭持续推力），除非实现计划明确列入并单独验收。

## 5. 敌方 AI：行为规格

### 5.1 输入空间（与玩家同构）

AI 输出应映射到与玩家相同的参数域（名称可与 `BattleContext` 对齐）：

- **施力点** `ContactPointWorld`：敌方笔碰撞体表面合法点（射线或候选点采样）。
- **方向** `LaunchDirection`：与玩家一致的单位向量语义（与拖拽 UI 一致）。
- **力度** `LaunchForce`：与玩家一致的标量区间（可与 `maxDragDistance` 等配置对齐）。

### 5.2 策略分层（逻辑模块）

1. **感知**：己方与对方 `Rigidbody` 位姿、速度（若允许读）、台面边界、是否处于可行动回合。
2. **目标**：例如「提高对方掉落概率」「保守自保」「针对对方质心弱侧」；目标由 **策略配置**（SO 或表）驱动，而非写死在 MonoBehaviour。
3. **规划**：从候选 `(contact, direction, force)` 中评分；里程碑 1 可用 **有限随机采样 + 启发式评分**；后续可替换为迭代优化或子集仿真。
4. **校验**：越界力度、非法施力点、穿模点丢弃；无法找到合法解时的回退策略（例如中心弱击）必须定义。

### 5.3 难度与「性格」

- **难度旋钮**（示例）：采样数、力度噪声、方向角噪声、是否使用 L2 仿真辅助评分、规划时间上限。
- **性格**（可选）：激进（偏高力度）、稳健（偏向台心）、投机（偏好击打对方已倾侧）——用数据权重表达，代码侧保持同一决策接口。

## 6. 预测指示：表现规格

### 6.1 视觉

- **线/带**：从施力点或笔身参考点沿初速度方向延伸，可用颜色区分 **L0/L1/L2** 或「确定区 / 不确定区」。
- **落点/包络**：L1+ 可显示近似落地区域（椭圆或色带），而非单像素点，以降低虚假精确感。
- **遮挡与像素风**：与现有像素相机、`Table` 尺度协调；避免过粗线宽导致读数困难。

### 6.2 刷新与性能

- 拖拽连续变化时 **节流**（如每 N ms 或位移超阈值重算）；L2 仿真须有 **步数/时间上限**，防止低端机卡顿。
- 不在 `ActionState` 全弹道持续重算完整 L2（除非单独功能需求），默认仅 **蓄力阶段** 显示。

### 6.3 可访问性

- 色觉友好：预测线不只依赖红绿对比；可提供 **线型/脉冲动画** 辅助区分「预测」与「场景实体」。

## 7. 与改装/商店的关系

- **零件改变质量与弹射倍率**：预测与 AI 评分必须能读取 **与 `PenAssembly` / `PenPartData` 一致的运行时数据**（或只读快照），避免装配界面与战斗内不一致。
- **新零件效果**：若效果在发射后改变力（持续推力），默认 **AI 与预测均不保证** 处理该效果（见 §4 非目标），除非单独开任务验收。

---

## 8. 验收标准（GDD 层）

- **AI**：完成至少一种难度配置下的 **完整对局循环**（敌方回合可发射、进入 `ActionState`、与玩家共用结算规则）；无非法状态迁移；异常回合有日志。
- **预测**：蓄力阶段可见预测反馈；文档标明所用 **L0/L1/L2** 级别；与实机对比的已知偏差在实现计划或配置指南中列出。
- **回归**：玩家独奏流程（无 AI）行为与改动前一致，除非实现计划记载的有意变更。

## 10. 风险与开放问题

| 风险 | 缓解方向 |
|------|----------|
| L2 与主场景物理不同步 | 统一参数来源；版本化配置；必要时仅用于 AI 离线评分而非玩家 UI |
| AI 计算卡帧 | 分帧规划、异步 Job（若引入）、降低采样与仿真深度 |
| 双笔同时运动时的预测 | 默认只预测「当前发射笔」；对方视为静态或仅用位姿快照 |

**开放问题**（后续里程碑决策）：是否支持「同时乱斗」、是否暴露 AI 思考过程给观战、是否允许玩家关闭预测以降低视觉噪音。
